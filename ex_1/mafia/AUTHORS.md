## Студент: постановка, решения, приёмка

**Ход работы.** Студент определил порядок и содержание всех этапов. Этапы выдавались по одному, каждый со списком требований и вопросов, на которые ассистент обязан был ответить. Свод правил для сессии тоже задал студент:
- всё на русском;
- ничего не делать вперёд;
- после каждого этапа объяснять логику со ссылками на файлы и строки;
- сборка без предупреждений при `-Wall -Wextra -Wpedantic`;
- при неоднозначности сначала перечислить трактовки.

**Постановка этапов.** Студент сформулировал требования к каждой части:
- `SharedPtr` и его потокобезопасный счётчик;
- модель данных и протокол;
- воспроизводимый генератор с явным зерном;
- концепты, которые «реально работают», а не украшают;
- иерархия ролей без логики потоков;
- движок «разослать и дождаться» на долгоживущих нитях;
- ведущий;
- ночь «сначала собрать, потом разрешить»;
- условия победы;
- осмысленные боты;
- журналы, ranges, корутины;
- все дополнительные роли из задания, свой разбор YAML;
- ИИ-агент с требованиями безопасности: ключ только из окружения, откат на эвристику при любом сбое, атомарный лимит за круг, отдельный журнал диалога, подмена адреса на локальный, тесты через поддельный сервер;
- финальная сдаточная проверка.

**Решения по правилам и устройству** (из предложенных вариантов или по своей инициативе):
- в первый день голосования нет;
- правило ничьей: если равны не все — переголосование среди равных; если равны все — голосование «выгнать всех разом»;
- доктор не может бесконечно лечить одного (замечание студента) — выбран вариант «не одного и того же две ночи подряд и себя один раз за игру»;
- комиссар — «проверяет или стреляет», как в задании: студент рассмотрел классический вариант «только проверяет» и отказался от него;
- реплик ботов должно быть много и разных;
- баланс: у маньяка должно быть меньше побед, у мирных — больше; ассистент по этому замечанию перенастроил эвристику;
- любые неверные параметры (например, отрицательное число игроков) должны давать понятную ошибку;
- дополнительные роли — все 35 из задания, а не минимальные три;
- ИИ-агент — через бесплатные API (статья на Хабре);
- `--interactive` обязателен для сдачи: место пользователя — по зерну или `--seat N`, роль — случайная, как у всех; открытые/закрытые объявления — сделать вместе с ним;
- предел партии — 317 дней (было 50: при 100 игроках не хватало); больше 100 игроков без `--interactive` — протокол только в журнал, в консоли «Да, это будет долго …» и итог.

**Проверка.** Студент принимал каждый этап по объяснениям ассистента и задавал уточняющие вопросы. Например: что за выстрел комиссара; что произошло, когда работа прервалась; можно ли после сжатия контекста получить полный диалог.

## ИИ-ассистент: реализация, тесты, объяснения

- **Весь исходный код** в `src/`, `tests/`, `tools/`, сборочные файлы (`Makefile`, `CMakeLists.txt`), конфиги в `config/`, `README.md`, этот файл и `docs/defense.md`.
- **Проектирование** в рамках поставленных требований:
  - разбиение на модули;
  - протокол «запрос/ответ» с неизменяемым снимком;
  - ночь как чистая функция-конвейер;
  - каталог возможностей ролей, построенный из концептов при компиляции;
  - два движка с одинаковым поведением;
  - схема передачи ключа API через канал.
- **Перечни трактовок** при неоднозначностях и рекомендации, из которых студент выбирал.
- **Тесты** (21 программа) и их проверка:
  - ThreadSanitizer;
  - сборка с `-Werror`;
  - «мутационные» проверки: умышленно ломал код и убеждался, что тест падает;
  - массовый прогон партий.
- **Объяснения** после каждого этапа: зачем нужна каждая сущность, какие были альтернативы, кто владеет данными и кто их меняет.
- **Отладка**: найденные гонки, предупреждения компилятора, перекосы баланса. Каждая правка обсуждалась в диалоге.
